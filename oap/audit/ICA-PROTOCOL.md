# Independent Closure Audit protocol

Later explicit audit action only. No running audit lane or model invoked by bootstrap.
Auditor is independent human or fresh isolated context with declared provenance;
do not seed strategy conclusions as premises. Input order: human scope, full current
architecture, exact current merged main, then strategic claims. Derive complete
requirements before using roadmap/report claims. Audit-only authority, no merge,
product edits, deployment or human acceptance.

Classify each relevant requirement IMPLEMENTED/PARTIAL/ABSENT/UNPROVEN. Link actual
runtime path, entry point, authority/persistence/routing, executable proof and
negative/failed/not-run cases at tested SHA. A test mocking its named boundary is
insufficient. Distinguish software, live Qwen, linguistic benefit, rights/resources
and DHA/deployment gates. Report context identity and exact PLAN/architecture hashes.

Use populated matrix and oap-ica template. check_ica enforces schema/scope/coverage/
revision/input ordering, not independence or semantic correctness. Exact audited
SHA must remain explicit when audit artifacts are published separately. Later code
change needs assessed delta or rerun; current helper conservatively requires rerun.
Every gap becomes provenance-linked bounded corrective/new work as appropriate;
repeat full architecture audit after remediation, not only ticket verification.
Strategy recommends; human judges milestone and deployment separately.
