# Bootstrap Acceptance — Implement and Execute These Checks

**Version 2.0.** These checks are the future generator's task. The input ZIP does
not contain a working OAP runtime or evidence that these runtime tests have run.
Source/ZIP validation by the document preparer is a different activity.

## 1. Verification levels and truthful status

Separate:

1. Input-package integrity and document consistency.
2. Generated file inventory and semantic source-to-projection review.
3. Executed helper tests with fake CLIs/GitHub and disposable Git/FIFO fixtures.
4. Read-only qualification of the installed real CLI/configuration discovery.
5. Owner-authorized later real OAP/model integration.
6. Product linguistic/runtime acceptance and independent milestone audit.

Levels 1–4 are bootstrap scope, with missing installed CLI facts reported honestly.
Levels 5–6 are not to be run merely to finish bootstrap. Do not report a fake CLI
as a real client compatibility test or an empty seeded matrix as a successful ICA.

Use PASSED, FAILED, SKIPPED, NOT RUN, BLOCKED, PENDING and MISSING distinctly.
A required skipped test is not pass. Structure can be valid while activation is
blocked by a missing authorized remote/profile/login. Missing Qwen/corpus does
not block ordinary offline OAP scaffold verification.

## 3. Semantic review protocol

The generator performs a second deliberate pass after authoring all role files:

- Compare every compact coding clause to full source meaning, including order,
  exceptions, authority, negation, quantifiers and failure paths.
- Look for hidden mandatory reads that undo context savings.
- Check strategic AGENTS really contains full decision/review duties rather than
  saying only "see compact coding instructions".
- Inspect D0/D1/D2 and anti-garbage rules together: ordinary failures do not become
  critical entries, and D2 cannot be reclassified merely to keep the loop moving.
- Check required human dispositions and context-loading policy exactly against the
  attached Concentrated chapter, not the obsolete earlier generated version.
- Reconcile all prompts, templates, helpers, setup docs and initial work orders to
  one suffix/DHA/FIFO/report contract.
- Trace all PLAN phase outcomes and eight MVP criteria; missing coverage cannot be
  hidden by a completed work-order count or a generic ICA placeholder.

Record this as generator semantic review, with source clauses and outcomes. It is
not a formal proof or an independent closure audit. If a genuinely independent
review was performed, record how; do not fabricate one just because two passes ran.

## 4. Test execution and bounded resources

Use an isolated OAP test environment or Python standard library. Install routine
missing local test tools only within permitted scope, never into Qwen's environment.
Fake agent executables capture argv/cwd/env and can simulate failures. Fake GitHub
transports have explicit verified/unverified states. Disposable Git repositories
prove SELF parent/path behavior. Temporary FIFO/tmux tests use timeouts and explicit
cleanup; do not touch the eventual real FIFOs to test signaling.

When tmux or a real CLI is unavailable, execute pure/fake tests and report the real
integration check NOT RUN/BLOCKED. Do not claim all acceptance rows passed if one
required layer was skipped. The receipt distinguishes completed local structure
from installed-client/runtime qualification and future product tests.

Negative tests must fail for the intended reason. Do not accept any nonzero exit
as proof of the target guard: inspect error classification and absence of forbidden
side effects. Check pre/post filesystem manifests and process ownership.

Do not write a fictitious remote SHA, test pass, linguistic improvement or human
acceptance. Source hashes are not software readiness. A truthful receipt may report
valid local scaffolding with activation blocked, rather than conceal missing authority.
