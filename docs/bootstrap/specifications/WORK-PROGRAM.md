# Preloaded Work Program and Closure Gates

**Version 2.0.** This is the bootstrap generator's expansion input, not an active
order list. It preserves the agreed 56-objective decomposition while making
context/governance and independent closure explicit.

## 1. Scope and planning discipline

Generate all `000-a` through `055-a` as **real, detailed, inert drafts** in the
versioned strategic seed and editable private draft copies. Do not execute any
of them. Do not generate their future remediation suffixes or invent evidence.
Do not replace this with seven broad objectives or 56 identical boilerplate files.

Each objective should normally fit a focused coding episode of roughly 30–60
minutes, excluding CI queues, data acquisition, live-model generation, annotation
and human gates. This is a decomposition target, not a timeout or a claim that
these tasks have already been benchmarked. Split an oversized planned objective
only through an explicit strategy-owned remap before activation; preserve IDs of
published history and document changed dependencies.

The draft roadmap is a coverage hypothesis. Strategy may remove an unneeded
optional experiment or add evidence/audit-driven work with H/A/E/I/C provenance;
it cannot remove an agreed product criterion to report completion. Mandatory
unavailable evidence remains UNPROVEN/BLOCKED, not an optional nonadoption.

The current bootstrap merely installs the scaffold. Objective 000 adopts the
owner-reviewed published baseline into the operational OAP process; it must not
repeat a completed bootstrap or implement the entire application.

## 3. Dependencies and phase exits

Generator must derive explicit dependencies from contracts/evidence and include
them in INITIAL-ROADMAP and each draft. Use this conservative starting structure:

```text
000–002  operational adoption, boundaries, CI
003–008  core contracts + source metadata/indexes
009–012  protected spans/token mapping + detector
013–019  review contract/client/isolation + acceptance
020–022  composed patching, CLI, demonstrator evidence -> ICA-DEMONSTRATOR
023–026  real/negative data and frozen evaluation split
027–032  optional analyzer, required morphology/lemma/phrase behavior, calibration
033–034  comparisons and measured quality
035–036  bounded execution/queue/cancellation
037–043  narrow API capture/isolation/envelope/failure/live evidence
044      experimental MVP evidence -> ICA-MVP
045–048  data/support/resource/negative-evidence expansion where justified
049–054  package/health/integration/rehearsal/abuse/rights documentation
055      verified-service evidence -> ICA-SERVICE -> relevant human DHA/gates
```

The default order is ascending, but the graph must identify real prerequisite
seams instead of blindly stating that every previous file is required. One
operational objective/PR is active at a time. Internal independent work may be
replanned around a genuinely unavailable external prerequisite after explicit
recorded disposition; do not silently skip an unresolved PR or pretend its phase
passed. A controlled trial is not a quality verdict without labels/evidence.

Human annotation, rights acquisition and protected live-service authorization
cannot be synthesized by coding. Prepare the permitted tooling and preserve
unavailable gates. Do not use D1 to pretend ownership of unknown data rights or
lower strict thresholds just to produce visible edits.

PLAN D01–D07, M01–M07, S01–S05 and all eight PLAN §16 criteria must map to at
least one implementing objective and a distinct evidence requirement. LR-001–LR-014
must all map to contract/negative tests. Optional collocation/full-statistics work
can conclude evidence-backed nonadoption only when its finalized acceptance
criteria explicitly allow it. Morphology required by the MVP cannot disappear
because one optional analyzer was not adopted.

## 4. Required content of every expanded draft

Each draft includes:

1. Unique ID/title/phase and `Status: DRAFT UNTIL STRATEGIC RECONCILIATION`.
2. H/A/E/I/C provenance with actual PLAN/architecture/source anchors. Seed orders
   normally use H/A; do not invent failing evidence/audits/CRIT entries.
3. Explicit prerequisites/dependency IDs, current-state VERIFY fields and
   protection of pre-existing local work.
4. Relevant LR IDs, compact-law clauses, source identities and gate summaries;
   full-source sections may be named for audit provenance without making all
   full documents mandatory coding context.
5. One testable product outcome and why this is a separately reviewable seam.
6. Scope, probable files/interfaces and concrete exclusions.
7. Objective-specific requirements, edge cases and numbered acceptance criteria.
8. Boundary-faithful positive/negative proof; focused/broader command templates;
   which facts are fake-unit, real integration, linguistic or deployment evidence.
9. Local setup, memory/time/call budgets, privacy and protected-resource limits.
10. Documentation/licensing/cleanup obligations and truthful unavailable-prerequisite
    behavior.
11. New/same-PR contract, exact immutable report/SELF protocol and no-merge law.
12. Decision classification and exact canonical DHA heading with `Decision: NONE`
    initially; any later APPEND must be genuinely investigated and complete.

Aim for several hundred substantive words per draft, without repeating whole
constitutions. Existing concise common law can be referenced. A first-created
future test path is a legitimate final verification target, not evidence that
that test exists already. Actual finalization markers must be resolved before
publication; never invent future main SHAs, PRs, model endpoints or corpus releases.

## 5. Closure audits are separate evidence, not self-awarded objectives

Generate three inactive independent-audit requests: ICA-DEMONSTRATOR-DRAFT,
ICA-MVP-DRAFT and ICA-SERVICE-DRAFT. They specify full source paths/milestone,
future verified current-main SHA, independent context, allowed read-only tests,
classification matrix and no-merge/no-deployment authority. Do not prefill PASS.

Objectives 022/044/055 assemble evidence and **request** an audit. They cannot
certify the audit they requested. Run later ICA from a fresh model/context or
independent human/audit agent, deriving requirements from full architecture and
human scope, not from this table. A completed queue does not establish that the
queue covered the product. A closure patch list may itself be incomplete.

Every gap becomes a bounded provenance-linked corrective/new order as appropriate.
Repeat ICA after remediation against the new merged product revision. A fresh
process alone does not prove independence if it is fed the strategic conclusion
as its premise; preserve audit-first input ordering and honest context provenance.

Generate a **populated requirements template**: actual PLAN/architecture criteria
and source anchors, with empty evidence fields and UNPROVEN initial classifications,
not an empty generic table. Suggested columns:

```text
Requirement ID | human milestone | full source/section | precise claim |
actual runtime path | current-main SHA | executable evidence and tested SHA |
negative paths | IMPLEMENTED/PARTIAL/ABSENT/UNPROVEN | gap | human gate
```

Include source-count truth, zero-call path, no history contamination, protected
spans, no whole-answer rewrite, fallback versus hard errors, held-out harm/benefit,
rights, final-envelope semantics and measured resource impact—not merely files.

## 6. Readiness and reporting

Generate READINESS defining development merged, internal demonstrator, experimental
MVP, external demo/pilot and qualified service/production as different claims.
Open D1 entries are permitted only before their registered gate. No relevant
human gate is cleared by all drafts having a corresponding merged PR.

COMPLETENESS uses separate progress axes for functional coverage, evidence
confidence, uncertainty reduction, debt/attack-surface reduction and capability
breadth. Initialize all product criteria as PLANNED/UNPROVEN/NOT RUN. Do not
compute a completion percentage from the number of generated files or commits.

The final service milestone may remain unproven if actual source rights, quality,
live integration or human judgment is unavailable. Honest incomplete evidence is
not authority to weaken PLAN or to fabricate a successful demonstration.
