### The 364 B v3 construction exposure - field-by-field attribution

Five documents, three mechanism shapes (all template T10-randomized; the
pre-seal dev diagnostic over the built set detected these BEFORE sealing, so
a set known to fail the hard axis was not put through the strategy
verification gate; the set was sealed and evaluated as-is because the
exposure is a verdict input, not a BLOCKED trigger, and a mid-round
implementation change would break the frozen protection identity with no
ordered re-freeze path):

1. **HTML-opening-tag-adjacent fence absorption - 2 x 139 B**
   (v3h-000713, v3h-001274; component family code-cpp). The last line of an
   adjacent structured-html component is an HTML OPENING-tag line
   (`<table>…` / `<ul>…`, a complete multi-tag line); it opens a
   CommonMark type-6 HTML block that runs to the first internal blank line,
   absorbing the code component's fence line and the first code lines
   (structural, covered); the remaining code lines parse as paragraph text
   and are exposed (139 B each: the code lines' non-machine text; machine
   tokens inside - URLs, paths, inline code, identifiers - are covered by
   the residual classes). R1's ordered predicate is closing-tag-scoped, so
   this complement shape is NOT covered by the released R1 and R1
   correctly did not fire (v3 R1 insertions = 0). This is a NEW bounded
   composition shape surfaced by the fresh pool (the 008-g 51 B pool
   produced the closing-tag variant); it is a pre-008-h design fact (the
   dev corpus never composes it: dev regression 0), and it is addressable
   at the builder/label-oracle level, not by a residual recognizer.
2. **xml-fragment class boundary (non-ASCII attribute) - 2 x 30 B**
   (v3h-000625, v3h-001241; component family structured-xml). In a
   single-line multi-tag XML line, the tags with fully-ASCII names and
   attributes parse as recognised inline HTML (structural, covered); one
   tag carries a non-ASCII (Slovenian) ATTRIBUTE NAME, which the dialect's
   inline-HTML rule (ASCII-only attribute names) does not recognise, so
   that tag's bytes become candidate prose; the frozen xml-fragment class
   abstains because the tag NAME is in the ASCII dialect vocabulary (v2
   parity guard) - so the tag delimiters/name bytes are exposed (18 + 10 +
   2 B) while the interior machine tokens (an identifier, a number) are
   covered by their own classes. Class-boundary behaviour of the frozen
   008-g spec; the trigger decision (tag-name based) cannot see
   attribute-shape recognition failures.
3. **Display-dollar pairing across a malformed component - 1 x 26 B**
   (v3h-001307; component family math-display-dollar). An adjacent
   malformed-incomplete-display-dollar component (unterminated `$$` opener
   plus a prose line) causes the parser to pair its opener with the
   COMPLETE component's opening `$$` (the DisplayMath event spans the two
   lines, structural); the complete component's TeX body then parses as
   paragraph text, where the frozen residual classes cover numbers,
   identifier runs, and brace groups but not TeX command names (`\frac`,
   `\quad`, `\text`) or the `=` operator (14 + 12 B). Dialect-pairing plus
   frozen class-boundary behaviour (no math-display-dollar residual class
   exists in the 008-g spec; the TeX classes are paren/bracket/env only);
   pre-existing.

**Pre-existence (008-g discipline):** reverting the single 008-h curated
